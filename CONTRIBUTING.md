# Как внести вклад в Enemy Highlight

[English](CONTRIBUTING.en.md) · [Development guide](docs/development.en.md) ·
[Руководство разработчика](docs/development.md)

Спасибо за интерес к проекту. Небольшие исправления можно сразу предлагать
через pull request. Для крупных функций сначала создайте issue: так можно
согласовать пользовательский сценарий, ограничения LOTRO Lua API и изменение
формата PluginData до начала реализации.

## Перед началом

1. Проверьте существующие issues и [roadmap](docs/roadmap.md).
2. Создайте отдельную ветку от актуальной `staging`.
3. Не добавляйте в коммит локальные материалы из `tasks/` или `docs/tasks/`.
4. Старайтесь ограничить pull request одной логической задачей.

## Требования к изменениям

- не добавлять покадровую обработку, если достаточно событий LOTRO;
- сохранять обратную совместимость PluginData и добавлять идемпотентную
  миграцию при изменении схемы;
- не включать сторонние библиотеки без предварительного обсуждения;
- обновлять пользовательскую документацию и roadmap вместе с изменением
  поведения;
- добавлять новые проверки в `docs/manual-test.md`;
- не коммитить пользовательские данные, локальные логи и внутренние task-файлы.

## Проверка

Автоматических интеграционных тестов для LOTRO UI нет. Перед pull request:

1. проверьте синтаксис изменённых Lua-файлов доступным Lua-парсером;
2. убедитесь, что манифест и пути модулей остались корректными;
3. выполните релевантные пункты
   [ручного сценария](docs/manual-test.md) в клиенте LOTRO;
4. проверьте загрузку без Lua-ошибок и повторную загрузку после сохранения
   данных;
5. проверьте Markdown-ссылки в изменённой документации.

Если часть проверки невозможно выполнить, явно укажите это в pull request.

## Pull request

В описании укажите:

- какую проблему решает изменение;
- что именно изменилось для пользователя;
- как изменение проверялось;
- затрагивается ли PluginData и как работает миграция;
- скриншоты для заметных изменений интерфейса.

Релизные теги создаются сопровождающим проекта только из стабильной ветки
`main`; подробности описаны в [инструкции по выпуску](docs/releasing.md).
