# Roadmap Enemy Highlight

**Русский** | [English](roadmap.en.md) · [К документации](README.md)

Этот документ фиксирует направления развития после `v0.2.0`. Порядок задач
может меняться после тестирования в LOTRO и обратной связи пользователей.
Номер этапа не является обещанием даты выпуска: содержимое версии может быть
разделено или перенесено, если прототип обнаружит ограничение API.

## Статус этапов

| Этап | Статус | Основная цель |
|---|---|---|
| `v0.1` | Выпущен | Пользовательские метки, заметки, поиск и индикатор цели |
| `v0.2` | Выпущен | Локализация и быстрый доступ к информации о цели |
| `v0.3` | Запланирован | Импорт/экспорт, уведомления и история текущей сессии |
| `v0.4` | Исследование | Псевдонимы, профили и расширенная модель базы |

`Backlog` содержит идеи без назначенной версии. Раздел «Отложено» описывает
функции, которые нельзя надёжно реализовать в текущем LOTRO Lua API.

## Видение продукта

Enemy Highlight развивается как персональная база игроков и инструмент быстрых
действий с текущей целью:

- пользователь сам решает, кого и как помечать;
- сохранённая информация должна быть доступна непосредственно в бою;
- интерфейс не должен мешать управлению персонажем;
- данные должны безопасно сохраняться, переноситься и восстанавливаться;
- функции должны одинаково работать в обычной игре и PvMP в пределах
  возможностей LOTRO Lua API.

Плагин не должен позиционироваться как радар, сканер находящихся рядом игроков
или автоматический определитель Свободных народов и Игроков-монстров: доступный
API не предоставляет для этого достаточно надёжных данных.

## Общие технические принципы

1. Не использовать покадровую обработку, если задачу можно решить событиями.
2. Все изменения PluginData должны иметь миграцию и сохранять старые записи.
3. Новые списки и поиск должны использовать сессионные индексы.
4. Любая функция уведомлений должна отключаться пользователем.
5. Закрытые окна не должны перехватывать клавиатуру или мышь.
6. Все визуальные изменения проверяются при разных разрешениях и UI scale.
7. Релиз выполняется только после ручной проверки в клиенте LOTRO.

## v0.2 — доступность информации и локализация

Цель версии: сделать плагин удобным для пользователей четырёх языков и
сократить число действий для работы с текущей целью.

### 1. Локализация EN/FR/DE/RU

Статус: выпущено в `v0.2.0`.

- пользовательские строки вынесены в таблицы локализации;
- добавлены `Locale/en.lua`, `fr.lua`, `de.lua` и `ru.lua`;
- `Automatic` определяет язык через `Turbine.Engine.GetLanguage()`;
- ручной выбор доступен в настройках и через `/eh language`;
- окна, кнопки, подсказки, сообщения и `/eh help` обновляются без перезагрузки;
- пользовательский текст использует шрифты с поддержкой кириллицы.

Критерии готовности:

- после смены языка все окна обновляются без удаления PluginData;
- отсутствует смешение строк разных языков;
- длинные переводы не обрезаются в стандартных размерах окон;
- английские имена продолжают сравниваться без учёта регистра.

### 2. Заметка на индикаторе

Статус: выпущено в `v0.2.0`.

Название метки остаётся постоянно. В любом режиме заметка показывается при
наведении, а короткий клик открывает отдельное окно редактирования. `/eh move`
разрешает перетаскивание, а `/eh lock` фиксирует только положение индикатора.

Задачи:

- tooltip содержит полное имя игрока, название метки и заметку;
- настройка `Show note tooltip` находится в `Manage labels`;
- пустая заметка не создаёт tooltip;
- короткий клик без drag открывает окно редактирования заметки;
- сохранение обновляет tooltip через событие модели без смены цели;
- после `/eh lock` hover и клик остаются доступны, но drag отключается.

Короткая вторая строка заметки с ограничением длины остаётся дополнительным
вариантом после проверки основного UX.

### Кандидаты для `v0.2.x`

Следующие улучшения не вошли в `v0.2.0` и могут быть выпущены отдельно или
перенесены в следующий этап после прототипирования.

#### Быстрые команды текущей цели

Планируемые команды:

```text
/eh target <label name>
/eh note target <text>
/eh info target
/eh remove target
```

Требования:

- понятная ошибка, если цель отсутствует;
- команды не должны работать с пустым именем;
- повторное назначение метки сохраняет заметку;
- удаление требует явной команды и сообщает результат в чат;
- многословные названия меток и заметки поддерживаются.

#### Небольшие настройки интерфейса

- скрытие и повторное включение плавающей кнопки;
- прозрачность индикатора;
- предпросмотр индикатора в `Manage labels`;
- сброс позиций окон и индикатора;
- восстановление элементов, случайно перемещённых за границы экрана.

## v0.3 — переносимость и быстрые реакции

Цель версии: защитить пользовательские данные и сделать метки полезнее во время
частой смены целей.

### 1. Импорт и экспорт

Добавить отдельное окно с многострочным текстовым полем.

Экспорт должен включать:

- версию формата;
- пользовательские метки и RGB-цвета;
- записи игроков и заметки;
- при необходимости — настройки отображения отдельным блоком.

Импорт должен поддерживать:

- `Merge` — добавить новые записи и обновить совпадающие;
- `Replace` — заменить текущую базу после подтверждения;
- предварительную проверку данных до изменения PluginData;
- отчёт: добавлено, обновлено, пропущено, ошибки;
- отказ от частичного импорта при повреждённой структуре.

Критерии готовности:

- экспорт можно скопировать и импортировать после перезагрузки клиента;
- повреждённые данные не удаляют существующую базу;
- конфликтующие метки обрабатываются предсказуемо;
- импорт большой базы не создаёт заметной паузы при обычных объёмах данных.

### 2. Уведомления для меток

Для каждой метки можно выбрать реакцию при назначенной текущей цели:

- без уведомления;
- сообщение в чат;
- временная подсветка рамки;
- короткая визуальная анимация;
- звук, если стабильный API и подходящий ресурс подтвердятся прототипом.

Ограничения:

- уведомление срабатывает только после выбора цели;
- одинаковая цель не должна создавать спам при повторных событиях;
- должен быть общий переключатель уведомлений;
- визуальный эффект не должен использовать постоянный покадровый обработчик.

### 3. История последних целей

Сессионный список последних выбранных персонажей:

- имя;
- назначенная метка или `Unknown`;
- время последнего выбора в рамках сессии;
- действия `Add`, `Edit`, `Info`.

По умолчанию история не сохраняется между перезапусками. Возможность постоянной
истории оценивается отдельно с учётом приватности и размера PluginData.

## v0.4 — расширенная модель игроков

Цель версии: поддержать долгосрочное ведение базы и разные сценарии игры.

### 1. Псевдонимы игрока

- несколько имён для одной записи;
- точное сопоставление цели по основному имени или псевдониму;
- защита от назначения одного псевдонима разным игрокам;
- отображение основного имени в списках;
- миграция существующих записей без изменения ключей пользователя.

### 2. Профили

Возможные профили:

- общий;
- PvMP;
- рейдовый;
- пользовательский.

До реализации необходимо определить:

- могут ли профили наследовать общие метки;
- как переносить игрока между профилями;
- какой профиль загружается при старте;
- нужно ли разделять профили по персонажам или только внутри серверной базы.

### 3. Расширенный поиск и сортировка

- опциональный поиск по заметкам;
- сортировка по имени, метке и времени изменения;
- фильтр `Has note`;
- избранные игроки;
- сохранение выбранного режима сортировки.

### 4. Контекстные действия LOTRO

Провести отдельный прототип `EntityControl` для текущей цели:

- открытие игрового контекстного меню;
- назначение цели через собственный элемент;
- совместимость со Свободными народами, Игроками-монстрами и NPC;
- отсутствие конфликтов с заблокированным индикатором.

Функция включается в релиз только после подтверждения стабильного поведения в
клиенте.

## Отложено из-за ограничений API

### Автоматическое сканирование игроков рядом

Не планируется без появления официального API, предоставляющего безопасный
список окружающих персонажей. Текущий `TargetChanged` сообщает только о цели,
которую пользователь уже выбрал.

### Автоматическое определение стороны PvMP

Не планируется как обязательная логика. PvMP-цель может возвращаться как
`Actor` без доступного `GetAlignment()`, поэтому результат нельзя считать
надёжным.

### Масштабирование Lua UI новыми методами Window

Отложено. В LOTRO Update 46.2.1 поддержку Lua UI scaling временно отключили, а
новые методы `Window` удалили до дополнительной доработки совместимости:

- https://www.lotro.com/update-notes/lotro-update-46-2-1-release-notes-en

До возвращения стабильного API используются собственные размеры, ограничения и
проверка позиции относительно экрана.

## Процесс выбора следующей задачи

Перед началом крупной функции:

1. зафиксировать пользовательский сценарий;
2. проверить ограничения LOTRO Lua API небольшим прототипом;
3. определить изменения PluginData и миграцию;
4. добавить сценарии в `docs/manual-test.md`;
5. реализовать функцию в `staging`;
6. проверить производительность и интерфейс в LOTRO;
7. только после этого переносить изменения в `main` и выпускать релиз.
