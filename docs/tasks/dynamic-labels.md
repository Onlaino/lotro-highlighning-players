# Динамические метки и настройка индикатора

## Цель

Заменить три жёстко заданных статуса на пользовательские метки. После
обновления плагин по-прежнему создаёт `Friend`, `Neutral` и `Enemy`, но
пользователь может переименовывать их, менять цвета, добавлять новые и удалять
неиспользуемые метки.

Экранный индикатор выбранной цели должен использовать имя и цвет назначенной
метки. Его размер настраивается пользователем.

## Принятые решения

### Модель меток

Каждая метка содержит:

- стабильный идентификатор, который не меняется при переименовании;
- отображаемое имя;
- цвет в виде компонентов `red`, `green`, `blue` от `0` до `255`;
- порядок отображения.

Изначально создаются:

| ID | Имя | Цвет |
|---|---|---|
| `friend` | `Friend` | зелёный |
| `neutral` | `Neutral` | оранжевый |
| `enemy` | `Enemy` | красный |

Новые идентификаторы генерируются внутри PluginData и не зависят от имени.
Это позволяет безопасно переименовать метку без изменения всех записей.

Имена меток обязательны, ограничены 32 символами и уникальны без учёта
регистра. Разрешены пробелы. В командах после имени игрока используется вся
оставшаяся часть строки, поэтому поддерживаются многословные имена меток.

### Удаление

- Нельзя удалить последнюю оставшуюся метку.
- Нельзя удалить метку, пока она назначена хотя бы одному игроку.
- Окно показывает количество назначенных игроков и объясняет причину отказа.

Такой вариант исключает неявное удаление записей и неожиданную массовую смену
отношений. Пользователь сначала переносит или удаляет связанные записи.

### Выбор метки в формах

Фиксированные три кнопки заменяются динамической прокручиваемой палитрой:

- каждая метка отрисовывается отдельной строкой с цветным образцом и именем;
- выбранная строка явно содержит `[selected]`;
- при нехватке места используется вертикальная прокрутка;
- палитра немедленно обновляется при добавлении, удалении, переименовании или
  смене цвета и одинакова в главном окне и карточке игрока.

В главном окне список категорий отображается вертикально и прокручивается. Это
масштабируется лучше горизонтальных вкладок при произвольном числе меток.
Категория `All` располагается первой, показывает общий счётчик и выполняет
поиск по именам во всей базе. Результат дополнительно показывает цвет и имя
назначенной метки. Выбор `All` не изменяет метку формы добавления.

### Окно управления

Отдельное окно `Manage labels` содержит:

- прокручиваемый список меток и число назначенных игроков;
- поля имени и RGB-компонентов;
- цветной предпросмотр;
- действия `New`, `Save`, `Delete`;
- поля максимальной ширины и высоты экранного индикатора;
- кнопку применения пределов автоматического размера.

Окно открывается кнопкой из главного окна и командой `/eh labels`.

### Размер индикатора

Размер рассчитывается автоматически по длине названия метки. Короткие названия
получают компактную плашку, длинные расширяют её и при достижении предела
переносятся на следующую строку. Подсчёт символов учитывает UTF-8, а не только
байтовую длину строки.

В окне управления задаются верхние пределы:

- максимальная ширина: `60..300` пикселей;
- максимальная высота: `20..80` пикселей.

Автоматический размер выбран вместо resize-handle мышью: собственная зона
изменения размера конфликтовала бы с перетаскиванием индикатора. После `/eh
lock` плашка не перехватывает игровые клики.

### Постоянная кнопка запуска

Небольшая кнопка с собственной иконкой глаза-цели и тремя цветовыми маркерами
постоянно находится поверх игрового интерфейса. Короткий клик переключает
видимость главного окна, а drag перемещает кнопку. Позиция сохраняется в
серверных настройках PluginData. Кнопка не зависит от выбранной цели и не
скрывается вместе с индикатором статуса.

### Миграция PluginData

Версия данных повышалась с `1` до `2` для динамических меток. Версия `3`
переносит общие `width` и `height` в пределы автоматического размера
`maxWidth` и `maxHeight`.

При загрузке старых данных:

1. создаются три стандартные метки;
2. `record.status` переносится в `record.labelId`;
3. старые записи и заметки сохраняются;
4. прежний размер индикатора сохраняется как предел автоматического размера.

Миграция идемпотентна: повторная загрузка уже обновлённых данных не создаёт
дубликаты.

## Производительность

### Текущие горячие пути

- Цель читается только по событию `TargetChanged`; покадрового обработчика нет.
- Поиск точного имени уже выполняется по хеш-таблице `players[normalizedName]`
  за амортизированное `O(1)`.
- PluginData загружается один раз и не читается при каждой смене цели.
- Списки строятся только при открытом окне или изменении данных.

### Сессионный индекс

Для списков создаются общий массив `allRecords` и индекс
`labelId -> sorted records`. Они живут только в памяти сессии и перестраиваются
после добавления, изменения или удаления игрока. Глобальный поиск фильтрует
общий массив, поиск в конкретной метке — только её массив, а счётчики получаются
без полного прохода по базе.

Периодическая очистка не используется. Она создавала бы лишние перестроения и
риск устаревших данных. Вместо этого применяется детерминированная инвалидация
после мутаций — кэш всегда соответствует PluginData в памяти.

### Практическая проверка

В LOTRO необходимо проверить:

1. отсутствие Lua-ошибок при быстрых сменах цели;
2. отсутствие заметной задержки с 100, 500 и по возможности 1000 записей;
3. ввод глобального поиска и поиска в большой категории;
4. массовое переключение категорий;
5. изменение цвета/имени метки при выбранной цели;
6. отсутствие фоновой активности при закрытых окнах и неизменной цели.

## Критерии готовности

1. Старые записи автоматически сохраняют статусы и заметки.
2. Метки можно создавать, переименовывать и перекрашивать.
3. Неиспользуемые метки можно удалить; опасное удаление блокируется.
4. Все формы и списки обновляются без перезагрузки плагина.
5. Индикатор показывает актуальное имя и цвет метки.
6. Размер зависит от текста и не превышает сохранённых пределов.
7. `/eh add` принимает имя пользовательской метки, `/eh labels` открывает
   управление.
8. Точный поиск цели остаётся `O(1)`, списки используют сессионный индекс.
9. Главное окно открывается командой `/eh` и постоянной кнопкой-иконкой.
10. Категория `All` ищет по всей базе и показывает метки результатов.
